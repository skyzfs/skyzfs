Most doubtful
- **`a_read_of_an_unflushed_record_is_not_answered_from_a_failed_log`**: the head test asserts the right clause, but I could not show it can fail on the simulated disk except by a thread race. The real-file window (a read after the device's failed flush, collected before the store settles the sync) is a design question, not only a test gap; the log store closed it with a checksum.
- **The two block rows (create, open)**: marked PARTLY mainly for the 2× boundary. If the reviewer takes "4× refused, 1× accepted, defect noticed" as enough, both are HELD. The missing error-field and directory-sync assertions are cosmetic.
- **`a_sync_that_cannot_be_begun_is_made_by_the_worker`**: "tried again later" is in the author's own statement of the property but not in the port. `begin_sync` keeps no state today, so it holds by construction; it is just untested.
- **The two rows on unit versus block**: held only for the cache writer; the served direct-I/O path cannot show a neighbour loss in this model. This is documented, not hidden.
- **The two marker-order rows**: called LOG-ONLY because the design reverses them. I did not check whether the in-place counterpart ("no client is told failed before the observer, the daemon's failure note, is told") is asserted. `the_failure_is_told_before_the_marker` orders observer against marker, not observer against answers. The store's single thread gives it by construction (`fail()` runs before any completion); the transport-side order is in tests outside these 26 rows.
- **`no_wake_is_lost_between_a_readers_look_and_its_wait`**: the port is probabilistic where the original was event-driven.
