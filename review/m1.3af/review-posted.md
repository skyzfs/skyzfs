### What you asked me to judge

**1. The race.** Right. On Linux, std's `Condvar::wait` reads the futex word, then releases the lock, then sleeps only if the word is unchanged. `notify_one` changes the word and wakes one sleeper.
- **The gap.** A thread that `wait()` (pool.rs:185) has counted is past `waiting += 1` and holds no lock, but may not yet sleep. A push in that gap wakes one thread that is asleep. The thread not yet asleep then finds the word changed and returns at once.
- **What the test counts.** Two threads return for one job. The second finds `jobs` empty and counts a futile wake.
- **The pool is right.** It asked for one wake.
